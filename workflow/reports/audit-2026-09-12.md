# SkellySpeak audit — 12 September 2026

Subsequent implementation and verification: [remediation report](audit-fixes-2026-09-12.md). Findings below describe the original audited checkpoint.

The recent work builds and its existing tests pass, but it is not free of consequential defects. This audit identifies **12 actionable findings: one P1, nine P2s and two P3s**. The most urgent is factory reset bypassing workspace ownership. The other main concerns are persisted server error text, inference outside the normal execution lifecycle, stale frontend projections, and lost persona edits.

P1 means fix urgently because ordinary use can destroy data. P2 means a demonstrated correctness/security problem or a concrete execution-contract gap. P3 means a lower-frequency defect or validation inconsistency. These priorities describe engineering impact; they are not CVSS scores.

**Findings**

**A01 · P1 — Factory reset can erase a workspace owned by another running instance.**

[factory_reset.rs:252](/Users/jon-mac-mini/code-stuff/github/freemocap/other/skellyspeak/src-tauri/src/factory_reset.rs:252), [store.rs:84](/Users/jon-mac-mini/code-stuff/github/freemocap/other/skellyspeak/src-tauri/src/store.rs:84), [StartupRefusal.tsx:16](/Users/jon-mac-mini/code-stuff/github/freemocap/other/skellyspeak/src/features/startup/StartupRefusal.tsx:16).

`Application::start` treats lock acquisition failure like an incompatible database: it opens the refusal screen with no Store. That screen exposes Factory Reset. Reset ignores a failed `state.lock()`, reads the credential index anyway, and proceeds to delete files. It neither obtains nor retains exclusive workspace ownership. Even the normal reset path drops the Store—and its file lock—before deleting the directory. On Unix, an open/locked file can still be unlinked; the lock does not protect the path against this deletion.

A synthetic probe using the actual extracted deletion helpers held the workspace lock, demonstrated that a second lock failed, and then successfully deleted both the database path and the lock path. No real application data was used. This also invalidates the export comment claiming a refused workspace cannot have a writer: the other process can still be writing.

Fix: distinguish ownership refusal from schema refusal; disable destructive recovery while another instance owns the workspace. Reset/export must acquire an independent exclusive ownership guard before touching files and retain it through completion. Add a two-process regression test. This is the release-blocking finding.

**A02 · P2 — Deferred cleanup trusts arbitrary filesystem paths.**

[factory_reset.rs:83](/Users/jon-mac-mini/code-stuff/github/freemocap/other/skellyspeak/src-tauri/src/factory_reset.rs:83), [factory_reset.rs:116](/Users/jon-mac-mini/code-stuff/github/freemocap/other/skellyspeak/src-tauri/src/factory_reset.rs:116).

`pending-cleanup` is a newline-delimited list of paths; startup recursively empties every listed directory without checking it against the app's allowed cleanup roots. Symlink rejection at the root is useful, but does not reject a perfectly ordinary unrelated directory. A synthetic pending record naming an unrelated temporary directory caused its sentinel file to be deleted.

This requires the ability to alter the app's private local cleanup record or an erroneous producer; it is **not** a demonstrated remote exploit or privilege escalation. Nevertheless, a persisted recovery record should not grant unrestricted recursive-deletion authority at the next launch. Store a small set of cleanup kinds, resolve their paths from trusted configuration, and reject unexpected destinations. Test malformed, unrelated and partially completed records.

**A03 · P2 — Non-429 server errors can persist arbitrary response content.**

[hosted.rs:98](/Users/jon-mac-mini/code-stuff/github/freemocap/other/skellyspeak/src-tauri/src/hosted.rs:98), [grouped.rs:264](/Users/jon-mac-mini/code-stuff/github/freemocap/other/skellyspeak/src-tauri/src/grouped.rs:264), [execution.rs:1154](/Users/jon-mac-mini/code-stuff/github/freemocap/other/skellyspeak/src-tauri/src/execution.rs:1154).

The new refusal decoder copies any string `detail` into `AppError.message`, capped at 300 characters. This helper also handles Custom URL responses. Ordinary execution subsequently saves that message in `attempts.error` and, for some operations, turn context. A custom server returning HTTP 400 with echoed authorization or request text can therefore put that content into durable local records. Length limiting is not redaction. A probe of the actual decoder confirmed that synthetic secret/content sentinels survive unchanged.

The current hosted server's authored errors and existing redacted diagnostics are useful protections; they do not establish the same contract for every Custom URL deployment. Use validated error codes and locally authored messages, with a generic status/request-ID fallback. Add non-429 redaction tests through a real loopback custom request and attempt persistence. No actual credential disclosure was observed.

**A04 · P2 — Persona generation bypasses execution lifecycle controls.**

[lib.rs:511](/Users/jon-mac-mini/code-stuff/github/freemocap/other/skellyspeak/src-tauri/src/lib.rs:511), [lib.rs:556](/Users/jon-mac-mini/code-stuff/github/freemocap/other/skellyspeak/src-tauri/src/lib.rs:556), [NewPersonaDialog.tsx:53](/Users/jon-mac-mini/code-stuff/github/freemocap/other/skellyspeak/src/features/guided/NewPersonaDialog.tsx:53).

Generation uses the shared capacity permit and checks an existing hold, but directly awaits the provider. It does not check the app-wide paused flag, revalidate connection authority after the asynchronous keychain read, retain an attempt receipt, or cancel when its dialog closes. Its provider result also bypasses the normal durable refusal/usage lifecycle. A user can close a generating dialog and start another while the original call continues; the capacity limit bounds simultaneous calls, not their visibility or recoverability.

The missing activity record is already acknowledged in `workflow/frontend-organization.md`; this finding extends that documented debt to pause, cancellation and credential-change behavior. Hosted server accounting still applies—this is not a claim that hosted calls escape server billing. Introduce an explicitly owned non-conversation operation, or an equivalently complete lifecycle, with a durable receipt, cancellation and authority checks. Test pause, delayed keychain access followed by disconnect, dialog disposal, and restart. No paid provider calls were made to reproduce this source-level gap.

**A05 · P2 — Settings reads can overwrite a newer scope with an older one.**

[settings.ts:82](/Users/jon-mac-mini/code-stuff/github/freemocap/other/skellyspeak/src/state/settings.ts:82), [GuidedPage.tsx:254](/Users/jon-mac-mini/code-stuff/github/freemocap/other/skellyspeak/src/features/guided/GuidedPage.tsx:254).

Every `load()` unconditionally adopts its eventual result. Conversation changes, modal opening and writes can overlap these multi-command reads. In a controlled probe, read A waited, read B selected French, and then A completed: the store reverted to Spanish and changed the document's UI language. Centralizing state in Zustand does not provide response ordering.

The stale record drives language selection, reading controls, evidence scope and audio preferences. Subsequent writes may be refused for stale scope, and language-dependent effects can move the UI again. Give all reads/adoptions a shared generation or scope authority, including post-save reads, and refuse stale completions. Apply the same principle to `session.refresh()`, which currently has the same unconditional adoption pattern.

**A06 · P2 — Returning to cached evidence fails to invalidate an abandoned read.**

[skill-evidence.ts:70](/Users/jon-mac-mini/code-stuff/github/freemocap/other/skellyspeak/src/state/skill-evidence.ts:70).

At the same settings revision, load Spanish evidence, start a French read, then return to Spanish before French completes. This is the selection-only/read-refresh path exposed by the store; a language save that increments the revision is a different case. The cached-Spanish early return leaves the French request current. Its response replaces the Spanish snapshot. The selector correctly hides the wrong-language value, but the shell's load effect has already run, so the current language can remain blank. A later `reload()` also follows the abandoned French request rather than the displayed language.

A deferred-promise test reproduced the sequence against the actual store. Set the desired scope and invalidate obsolete requests before accepting a cache hit. Also test queued reloads across scope changes: a stale request's `finally` currently shares the global trailing-read flag. Keep desired scope, request identity and cached result separate.

**A07 · P2 — Speech arriving after suspension can start playing.**

[speech.ts:15](/Users/jon-mac-mini/code-stuff/github/freemocap/other/skellyspeak/src/platform/audio/speech.ts:15), [speech-player.ts:38](/Users/jon-mac-mini/code-stuff/github/freemocap/other/skellyspeak/src/features/guided/speech-player.ts:38), [useMessageSpeech.ts:52](/Users/jon-mac-mini/code-stuff/github/freemocap/other/skellyspeak/src/features/guided/useMessageSpeech.ts:52).

`setPlaybackAllowed(false)` stops only the currently registered player. It stores no prohibition. If the app loses focus or becomes hidden while speech is still being generated/read, there is no player to stop; the late result registers and calls `audio.play()` without checking the lifecycle state. The hook's `active` flag describes the selected app surface, not OS focus or visibility.

The probe confirmed that registering a player after suspension is accepted. Retain the allowed/blocked state and check it before starting playback, including asynchronous completion. Verify with a delayed audio result after blur/visibility/suspend. Whether a particular mobile OS suppresses the sound independently is not a substitute for the app's own guarantee.

**A08 · P2 — Closing a persona editor loses list-field edits that have not blurred.**

[PersonaForm.tsx:22](/Users/jon-mac-mini/code-stuff/github/freemocap/other/skellyspeak/src/features/guided/PersonaForm.tsx:22), [PersonaForm.tsx:74](/Users/jon-mac-mini/code-stuff/github/freemocap/other/skellyspeak/src/features/guided/PersonaForm.tsx:74), [PersonaProfile.tsx:53](/Users/jon-mac-mini/code-stuff/github/freemocap/other/skellyspeak/src/features/guided/PersonaProfile.tsx:53).

Interests, opinions, facts, books, movies and quirks keep their edited text only inside `PersonaForm` until blur. The outer `flush()` saves the parent's draft, which still contains the previous list. Escape is intercepted before blur; flush resolves and the dialog unmounts. A component probe changed Interests and invoked the same close-time flush: no save occurred.

Make pending list input part of the form's flush contract or the parent's owned draft. Test Escape and all close paths with a focused list field, including invalid input. The nearby comment claiming focused fields are flushed is currently false. Normal mouse-driven blur tests do not cover this case.

**A09 · P2 — Clear leaves the persona dialog without a normal discard/close path.**

[PersonaProfile.tsx:27](/Users/jon-mac-mini/code-stuff/github/freemocap/other/skellyspeak/src/features/guided/PersonaProfile.tsx:27), [PersonaProfileDialog.tsx:14](/Users/jon-mac-mini/code-stuff/github/freemocap/other/skellyspeak/src/features/guided/PersonaProfileDialog.tsx:14).

Clear deliberately produces an invalid blank draft. Every normal dialog close then calls `flush()`, validation rejects, and closing is refused. There is no Restore saved/Discard changes action. A probe confirmed both rejection and the missing recovery control. Invalid edits and persistent save conflicts create the same trap. The separate New persona action can leave without that flush, making close behavior inconsistent.

Provide an explicit discard/restore path and route all exits through one policy. Preserve failed input until the learner chooses to discard it; do not require reconstructing a valid persona merely to close a dialog.

**A10 · P3 — Backup names collide within a second and can retain stale sidecars.**

[factory_reset.rs:173](/Users/jon-mac-mini/code-stuff/github/freemocap/other/skellyspeak/src-tauri/src/factory_reset.rs:173), [factory_reset.rs:230](/Users/jon-mac-mini/code-stuff/github/freemocap/other/skellyspeak/src-tauri/src/factory_reset.rs:230).

Export uses a whole-second timestamp and `create_dir_all`, then overwrites matching files in that folder. A second export in the same second reuses it; sidecars present only in the first export remain. A synthetic test reproduced a newer main database alongside an older retained WAL. The actual damage on reopening depends on SQLite journal matching; the confirmed defect is that the claimed new copy is a mixed, nonexclusive directory.

Use an exclusively created unique directory and publish it only after the copy succeeds. Add same-timestamp, partial-copy and SQLite-reopen tests. The current export test copies arbitrary bytes, so it verifies file copying rather than recoverable database consistency.

**A11 · P3 — Native and frontend emoji validation disagree.**

[emoji.rs:37](/Users/jon-mac-mini/code-stuff/github/freemocap/other/skellyspeak/src-tauri/src/emoji.rs:37), [personaLimits.ts:12](/Users/jon-mac-mini/code-stuff/github/freemocap/other/skellyspeak/src/features/guided/personaLimits.ts:12).

The native validator accepts any single grapheme containing VS16 or the keycap combining mark without validating its base. It accepts `A` + U+FE0F and `x` + U+20E3; the frontend correctly rejects both. Native generated-persona validation therefore admits values the editor later cannot save. Separate probes verified both sides.

Use the same explicit sequence rules at both boundaries and a shared adversarial fixture set. Include invalid bases, lone selectors, flags, keycaps and ZWJ sequences. A selector expresses presentation intent; it is not proof that the base character has an emoji presentation.

**A12 · P2 — The docs build includes a confirmed vulnerable image parser.**

[Docs lockfile:10716](/Users/jon-mac-mini/code-stuff/github/freemocap/other/skellyspeak/skellyspeak-docs/package-lock.json:10716).

The separate docs audit reports **19 high-severity affected packages**, propagated from two advisories in **one underlying dependency, `image-size@2.0.2`**. Docusaurus's MDX image transform calls `imageSizeFromFile` on local image assets during compilation. Crafted ICNS and JXL/HEIF images can make the parser loop indefinitely. The discoverer's [technical report and fixtures](https://joshua.hu/image-size-infinite-loop-dos-vulnerabilities) describe the defects; [the ICNS advisory](https://github.com/advisories/GHSA-w3rx-r6r6-pgpr) and [JXL/HEIF advisory](https://github.com/advisories/GHSA-5p2g-fcmc-qvqq) identify the affected versions. npm reports no automatic fix available.

A bounded child-process probe against this checkout's installed package did not return for the published 16-byte ICNS fixture and was terminated after two seconds. The identified application exposure is a malicious image processed by the **documentation build**, such as a contributed asset. This is not evidence that an ordinary visitor can hang the deployed static site or that credentials/code execution are exposed. The dependency is inherited, not introduced by the final CSS commit.

Track the dependency remediation explicitly; use a reviewed compatible fix or bound/isolate image parsing before accepting untrusted assets. A generic `npm audit fix` is not an established remedy here. Include the docs lockfile in routine security scans—the clean root-package audit does not cover it.

**Quality observations and limits**

- The final CSS commit fixes the earlier disconnected split stylesheets and narrow checker coverage. The manifest now loads them and the checker walks all 15 sheets. I do not carry that superseded issue as an open finding. Computed layout, focus, touch sizing and device playback still need actual app/device inspection; parser checks and DOM tests do not establish those results.
- The state reorganization improves module boundaries, but comments overclaim guarantees such as “nothing can go stale” and “focused field” flushing. The reproduced races are evidence that those claims need tests or narrower wording. The Zustand reset mock also resets public state but not closure bookkeeping; tests that leave reads in flight need explicit isolation.
- Several active documents contain incompatible historical claims: `architecture.md` describes schema upgrades through v7 while source accepts only v11; README still names an obsolete application-data identifier, a 1.0.0 release target, unimplemented mobile recording, and superseded UI/state behavior. Consolidate current behavior into one status description and label historical checkpoints. Keep the new coaching design distinct from the current scoring implementation.
- The production entry chunk is approximately 622 kB minified / 198 kB gzip. Vite warns. That is a bundle-size observation, not a measured responsiveness defect. Do not start another broad reorganization without profiling the actual expensive path.
- Deterministic dead-module assertions and heuristic unused-export/CSS diagnostics have different confidence. Current warning-only tests should not be described as enforced absence of dead code. The fresh style gate is stronger, but a green suite still lacks the cross-scope, close-with-pending-input and hostile-response cases reproduced here.
- The server source is unchanged across this release range. Authentication, PKCE, destination-bound credentials, redirect refusal, bounded response handling, quota and concurrency tests provide useful evidence. I did not inspect production IAM, real user credentials, live provider behavior, signed installers, or actual device login/reset/voice. This was not a new full-history secret scan or a fresh Rust/Python advisory scan. The earlier `SECURITY-AUDIT.md` contains unresolved Linux dependency and repository-setting findings; its historical scans/settings checks must not be represented as fresh verification.
- The empty-data rebuild and refusal of incompatible schemas are explicit project decisions, so I have not recast the lack of migration as a defect. The problem is unsafe recovery around refusal, not that design decision.

Fix order: workspace ownership and bounded cleanup first; error redaction and generation lifecycle next; then settings/evidence/audio authority and persona draft handling. Repair the smaller export/emoji cases with focused regressions and track the docs image-parser exposure independently. Re-run affected checks after fixes and perform a disposable-data native recovery check before treating reset as safe. No finding above has been fixed by this audit.
