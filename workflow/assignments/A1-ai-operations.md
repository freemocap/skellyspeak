# A1 — AI Operations and model evaluation

## Current assignment

Start with a design/proposal conversation with the user. Read current root source
without editing it; write initial proposals in the dedicated task. No runtime
installation, model download, paid evaluation, Git write or deployment in this phase.

Recommend a small candidate set for Standard/Fast assignments and local inference
on the user's 24 GB unified-memory Mac mini. Determine the actual chip rather than
assuming it. Research current primary documentation and distinguish evidence,
estimates and unmeasured claims. Larger/smaller does not guarantee speed or quality.

Cover partner replies, translation, source-bound glosses and coaching first. Specify
schema/source validity and semantic quality, representative languages, p50/p95
latency, first useful result, throughput, cost, cold/warm loading, context/KV cache,
quantization, peak memory and concurrency. Preserve independent partial hydration.
Propose explicit budgets, downloads and a small synthetic-data experiment for review.
Do not claim generic benchmark scores establish application quality.

## Boundaries

Custom URL speaks the SkellySpeak server protocol. Ollama or LM Studio, if selected,
requires an intentional provider adapter behind the self-hosted server; the client
does not acquire arbitrary endpoint compatibility or automatic fallback. Standard
remains the active model role until evaluation justifies Fast assignments.

Language owns semantics and source contracts; Reliability owns admission, lifecycle,
accounting and security; Interaction owns presentation. AI Operations proposes
model routing and capability strategy. Integration resolves shared changes and owns
the ongoing hosted gloss failure investigation.
